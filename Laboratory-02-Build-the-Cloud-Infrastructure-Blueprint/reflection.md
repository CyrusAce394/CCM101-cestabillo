# Mission Reflection

Of the infrastructure primitives, compute resources seem to be the most foundational part. Applications require processing power and memory to perform business logic operations, to handle users' requests and to communicate with other layers such as storage and networking. Also, managing those resources successfully is impossible without Linux being an integral part of cloud computing. Being lightweight, open-source, and safe, Linux is used by major cloud vendors to run hypervisors, containers and enterprise VMs. The wide range of command line utilities helps engineers to examine the specifications of hardware and system performance metrics.

Preparing technical documentation before the actual deployment of any infrastructure is crucial. It ensures that the architecture has been assessed for potential security vulnerabilities, scalable solutions and efficient cost usage before investing the money into it. Documentation avoids the problem of misconfiguration of the systems and provides guidelines for troubleshooting, as well as audit log needed for collaboration.

With this laboratory exercise, I have gained experience in auditing of the server resources with the help of `lscpu`, `free -h`, `df -h` and `ip a` commands. I also have learned how to map physical hardware with the corresponding virtual services on the public cloud vendors such as AWS, Azure, and GCP, how to build basic architecture diagrams and write reports in Markdown format.

This mission is important for my GitHub portfolio. Instead of just keeping the scripts in my GitHub, I can showcase my structured deliverable cloud engineering work.
